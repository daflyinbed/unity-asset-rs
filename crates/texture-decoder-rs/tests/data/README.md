# Test data provenance

The `astcenc-*.astc` inputs prefixed `tiles-ldr-4x4` and `ldr-a-1x1-6x6`
are copied from Arm's astc-encoder, in the `vendor/astc-encoder` submodule
(`Test/Data`).

`astcenc-tiles-ldr-*-source.png` files are copied from the same source tree.
`astcenc-tiles-ldr-complex-4x4.astc` was compressed from the copied
`ldr-complex.png` with the `vendor/astc-encoder` `astcenc` reference encoder using the
linear LDR 4x4 profile. Its `.rgba` file is the tightly packed RGBA8 output
from that reference decoder. They form a byte-exact regression pair.

The reference project is Apache-2.0 licensed; see the repository
`LICENSE-APACHE` file.

The files under `etcpack/` are copied from the ETCPACK submodule
(`vendor/etcpack`), its `testing/testvectors_correct` directory. The PKM inputs and their
PPM, PGM, or TGA decompressed outputs cover ETC1 RGB8; ETC2 RGB8, sRGB8,
RGBA1, sRGBA1, RGBA8, and sRGBA8; and signed and unsigned EAC R11/RG11.
The tests convert the reference outputs to this crate's RGBA8 convention.
See `etcpack/licence.txt` for the ETCPACK package license.

The files under `compressonator/` are BC1–BC7 conformance fixtures generated by
`tools/gen_bcn_golden.cpp` (driven by `tools/gen_bcn_golden.sh`). Each fixture is
a `.bcn`/`.rgba` pair: the raw compressed block payload (the decoder input) and
the tightly packed RGBA8 output produced by the Compressonator reference
decoder (the `vendor/compressonator` submodule). The set covers BC1–BC5, all 14 BC6H modes (both UF16 and
SF16), and all 8 BC7 modes. BC6H half-float outputs are clamped to RGBA8 with
this crate's mapping. The tests compare the Rust decoder against these golden
outputs byte-for-byte and do not invoke Compressonator at run time.
Compressonator is MIT licensed; see `LICENSE-MIT-COMPRESSONATOR`.

The files under `bcdec/` are BC6H fixtures generated independently from
[iOrange/bcdec](https://github.com/iOrange/bcdec) (the `vendor/bcdec` submodule;
`bcdec_bc6h_half`, with the half-float output clamped to RGBA8 using this
crate's mapping). The `bc6h-{uf16,sf16}-lerp-round` blocks were chosen because
their interpolated weights straddle the `>> 6` rounding boundary: pixel 1 blue
(UF16) and pixel 11 green (SF16) differ by one between round-to-nearest and
truncation. They guard the `+ 32` rounding in the BC6H interpolator, which the
Compressonator goldens above cannot exercise because their blocks never land on
that boundary. bcdec is dual MIT/Unlicense licensed.

The files under `crunch/` are Crunch (CRN v1.04) conformance fixtures generated
by `tools/gen_crn_golden.sh`. The script synthesizes small 6×6 TGA sources and
six-face DDS cubemaps via `tools/gen_crn_source.py`, then compresses them to
DXT1 and DXT5 CRN with the `vendor/crunch` CLI. The cubemaps have three
mips (6×6, 3×3, and 1×1); every face has a distinct color, and the DXT5 source
also gives every face a distinct alpha pattern.

`tools/gen_crn_golden.cpp` uses the reference `crn_decomp.h` to transcode every
face and mip level. Each `.crn`/`.bc` pair contains the decoder input and its
raw BC block bytes. Blocks are row-major within a subresource, and cubemap
goldens concatenate subresources in face-major, mip-minor order. Faces use the
standard `+X, -X, +Y, -Y, +Z, -Z` order. The tests compare each Rust
`crn::decode` subresource against these goldens byte-for-byte without invoking
the reference project at run time. The 6×6 dimensions deliberately exercise
partial edge blocks. crunch (crnlib) is in the public domain.

The files under `crunch_unity/` are Unity-fork Crunch conformance fixtures
generated by `tools/gen_crn_unity_golden.sh`. The Unity fork (the `unity`
branch of the `vendor/unity-crunch` submodule) replaced upstream Crunch's
"chunk encoding" bitstream with an incompatible "reference encoding" scheme and
added ETC formats, so its files are not decodable by the `crn` module.
The script reuses `tools/gen_crn_source.py` for the 6×6 sources and the
`vendor/unity-crunch/crnlib/crunch` CLI to compress them to DXT1, DXT5, ETC1,
ETC2, ETC2A, ETC1S, and ETC2AS CRN, including three-mip cubemaps.

`tools/gen_crn_unity_golden.cpp` uses the Unity fork's `crn_decomp.h` to
transcode every face and mip level into the natural tightly-packed block layout
(the true `crnd_get_bytes_per_dxt_block` size, 8 bytes for ETC1 and 16 for the
others). Each `.crn`/`.bc` pair contains the decoder input and its raw block
bytes; cubemap goldens concatenate subresources in face-major, mip-minor order.
The tests compare each Rust `crn_unity::decode` subresource against these
goldens byte-for-byte without invoking the reference project at run time. Note
that unlike upstream crunch (public domain), the Unity fork is ZLIB licensed
(see `vendor/unity-crunch/license.txt`); the committed `.crn`/`.bc` fixtures
here are small synthetic payloads generated by it, not a redistribution of its
source.
